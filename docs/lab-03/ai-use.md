## Verification and human decisions

- The assistant’s proposed session, CSRF, password, migration, role, queue, status-transition, and User Management decisions were checked against the labsheet and recorded as contract decisions in `specification.md`.
- I retained authority over branches, commits, pushes, PRs, reviews, Project status, and merges. The agent did not treat one authorization as permission for another action.
- I rejected any suggestion to mark final-main, Project-board, formal approval, or PDF evidence complete before the real external facts existed.
- I corrected evidence claims when a test covered only smoke behavior, preserved Lab 2 route compatibility, and kept passwords and database credentials out of the repository.
- Verification used failing-first tests, focused and regression suites, TypeScript/Vite builds, guarded PostgreSQL migration/seed checks, Playwright runs, code review comments, and manual evidence inspection.

## Reflection

Lab 3 taught me that a working feature is only part of a reliable submission. The contract, branch order, ownership rules, migration safety, and evidence must agree with one another. AI suggestions helped me turn the labsheet into smaller Issues and identify useful tests, but I still had to decide whether a suggestion belonged to the current Issue, whether a route preserved Lab 2 behavior, and whether a result was strong enough to claim in the evidence.

I accepted the contract-first and failing-first workflow, then changed several outputs after checking the actual repository and review feedback. For example, I kept compatibility routes, narrowed an E2E claim from full mutation coverage to smoke coverage where that was what the test really proved, and left final-main and Project evidence pending instead of inventing screenshots or approvals. I also had to protect local credentials and use an isolated test database rather than copying secrets into documentation.

Human judgment remained necessary to interpret the rubric, control GitHub permissions, compare test output with the requirements, and decide when a test was blocked by environment configuration instead of passing. The main lesson is to treat AI as a fast engineering partner whose suggestions still require requirement-by-requirement review, executable tests, and honest evidence.
