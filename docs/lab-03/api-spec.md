# Lab 3 REST API Specification

This contract extends the Lab 2 API without trusting a client-supplied Requester context. The server is the authority for authentication, identity, ownership, role checks, validation, timestamps, status transitions, and safe errors.

## 1. Conventions and Authentication

- Base path is `/api`.
- JSON timestamps are ISO UTC strings. Successful mutation timestamps are generated by the backend.
- Login establishes an opaque server-side session in an `HttpOnly` `toktickit_session` cookie. The token is random and only its SHA-256 hash is stored in PostgreSQL.
- The cookie uses `SameSite=Lax`, `Path=/`, and `Secure` outside local HTTP development. Tokens are never stored in `localStorage` or `sessionStorage`.
- Successful login and `GET /api/auth/me` return a session-bound CSRF token. Authenticated unsafe requests send it in `X-CSRF-Token`.
- Credentialed CORS allows only the configured client origin. Login and unsafe requests validate Origin where present.
- `X-Requester-Id` is not used in Lab 3 and `requesterId` is never accepted in a Ticket body or multipart field.
- All protected endpoints check that the session is unexpired, not revoked, and associated with an active User. A User with `mustChangePassword=true` is limited to current-user, change-password, and logout behavior.
- Responses use `Cache-Control: no-store` for authentication, user, Ticket, comment, note, and Attachment data.

### Common error shape

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Please correct the highlighted fields.",
    "fieldErrors": {
      "email": "Email is required."
    }
  }
}
```

Never return password hashes, session/CSRF tokens except the intended client-memory CSRF token, raw credentials, storage paths, stored filenames, stack traces, or protected-resource existence details.

| Status | Meaning in this contract |
|---:|---|
| 200 | Successful retrieval or mutation returning a representation |
| 201 | Ticket, Attachment, User, Comment, or Note created |
| 204 | Successful logout with no response body |
| 400 | Malformed JSON/multipart/query or field validation failure |
| 401 | Missing/invalid/expired/revoked session or safe credential failure |
| 403 | Wrong role, password-change restriction, invalid Origin, or CSRF failure |
| 404 | Missing or inaccessible protected resource; same safe response for both |
| 409 | Duplicate email, invalid/stale workflow, inactive assignee, admin safety, or state conflict |
| 413 | Attachment/request exceeds the permitted size |
| 415 | Unsupported media or extension/MIME/signature mismatch |
| 429 | Login-attempt bucket is temporarily blocked |
| 500 | Safe unexpected server failure; details are logged server-side only |

## 2. Authentication Endpoints

### `POST /api/auth/login`

Public endpoint. JSON request:

```json
{ "email": "amina@example.test", "password": "Initial-Lab3!Password" }
```

Trim/lowercase email and validate the password field. On success return `200`:

```json
{
  "user": {
    "id": 1,
    "name": "Amina Rahman",
    "email": "amina@example.test",
    "role": "REQUESTER",
    "isActive": true,
    "mustChangePassword": true
  },
  "csrfToken": "returned-once-to-client-memory"
}
```

Set the session cookie. Return the same safe `401 AUTHENTICATION_FAILED` for invalid credentials and inactive accounts. Return `400` for malformed fields and `429 LOGIN_RATE_LIMITED` after five failures in the 15-minute key window.

### `GET /api/auth/me`

Requires a valid session. Return `200` with the same safe `user` shape and a current CSRF token. Return `401` for missing/expired/revoked/inactive sessions. Return `403 PASSWORD_CHANGE_REQUIRED` only when the caller attempts a non-allowed application endpoint; `me` itself remains available.

### `POST /api/auth/change-password`

Requires a valid session and `X-CSRF-Token`. JSON request:

```json
{
  "currentPassword": "Initial-Lab3!Password",
  "newPassword": "New-Lab3!Password-2026",
  "confirmPassword": "New-Lab3!Password-2026"
}
```

Validate the 12-128-character upper/lower/number/symbol rule, whitespace rule, current-password match, different-new-password rule, and confirmation. On success return `200` with the User and rotated CSRF token; clear `mustChangePassword`, rotate the current session, and revoke other sessions. Return `400` for fields, `401` for an invalid current password, `403` for CSRF/session restrictions, and `409` for a concurrent state conflict.

### `POST /api/auth/logout`

Requires a valid session and CSRF token. Delete/revoke the session and expire the cookie. Return `204`. Repeated logout is safe and returns `204` when no active session remains.

## 3. Authenticated Reference Endpoints

### `GET /api/categories`

Requires an authenticated User. Return active Categories in stable ID/name order:

```json
[{ "id": 1, "name": "Hardware" }]
```

### `GET /api/related-systems`

Requires an authenticated User. Return active Related Systems in stable ID/name order:

```json
[{ "id": 1, "name": "Campus Wi-Fi" }]
```

Reference failure returns safe `500 REFERENCE_DATA_UNAVAILABLE`.

## 4. Shared Ticket and Requester Endpoints

The Requester identity is always the authenticated `User.id`; no body/header can choose another Requester.

### `POST /api/tickets`

Requester only. Use one `multipart/form-data` request with text fields `categoryId`, `relatedSystemId`, `requestedPriority`, `summary`, `description`, and repeated file field `attachments` (zero-to-five). Do not include `requesterId`.

Validate existing Lab 2 limits plus active references. The server validates and buffers every field/file, stages bytes, begins the transaction, allocates the annual number, creates rows, moves staged UUID files, and commits only after every operation succeeds. Any failure compensates database and filesystem work.

Return `201`:

```json
{
  "ticket": {
    "id": 1,
    "ticketNumber": "TKT-2026-000001",
    "requester": { "id": 1, "name": "Amina Rahman", "email": "amina@example.test" },
    "category": { "id": 2, "name": "Hardware" },
    "relatedSystem": { "id": 1, "name": "Campus Wi-Fi" },
    "requestedPriority": "HIGH",
    "itPriority": "HIGH",
    "status": "NEW",
    "summary": "Campus Wi-Fi disconnects",
    "description": "The connection drops repeatedly during class.",
    "ticketOwner": null,
    "resolutionIndication": null,
    "createdAt": "2026-09-13T10:00:00.000Z",
    "updatedAt": "2026-09-13T10:00:00.000Z",
    "attachments": []
  }
}
```

Use `400` for validation/reference errors, `401/403` for auth restrictions, `413/415` for file rules, and safe `500 TICKET_CREATE_FAILED` for unexpected failures.

### `GET /api/tickets`

Requester only; lists only the authenticated Requester's Tickets. Query parameters:

- `search`: Ticket Number, Summary, or Description; trimmed, maximum 100 characters;
- `categoryId`, `relatedSystemId`, `priority`, `status`;
- `sort`: `updatedAt|createdAt|ticketNumber|summary|requestedPriority`;
- `order`: `asc|desc`;
- `page`: positive integer, default `1`;
- `pageSize`: `10|25|50`, default `10`.

Default ordering is `updatedAt desc`, then `id desc`. Return `200`:

```json
{
  "items": [
    {
      "id": 1,
      "ticketNumber": "TKT-2026-000001",
      "summary": "Campus Wi-Fi disconnects",
      "category": { "id": 2, "name": "Hardware" },
      "relatedSystem": { "id": 1, "name": "Campus Wi-Fi" },
      "requestedPriority": "HIGH",
      "itPriority": "HIGH",
      "status": "NEW",
      "ticketOwner": null,
      "createdAt": "2026-09-13T10:00:00.000Z",
      "updatedAt": "2026-09-13T10:00:00.000Z"
    }
  ],
  "pagination": {
    "page": 1,
    "pageSize": 10,
    "totalItems": 1,
    "totalPages": 1,
    "hasPreviousPage": false,
    "hasNextPage": false
  }
}
```

Invalid query values return `400`; a valid page beyond the end returns an empty `items` array with metadata.

### `GET /api/tickets/:ticketNumber`

Requester receives only an owned Ticket. IT Staff/Administrators may use this endpoint for permitted Ticket Detail access. Return `200` with `{ "ticket": <detail> }` and never expose storage paths, stored filenames, password/session data, or Internal Notes to a Requester. Missing/cross-owner returns the same safe `404 TICKET_NOT_FOUND`.

### Attachment endpoints

`GET /api/tickets/:ticketNumber/attachments` returns active and removed metadata to an owner, IT Staff, or Administrator. `POST /api/tickets/:ticketNumber/attachments` uses one multipart field `file` and is Requester-owner only. `GET /api/tickets/:ticketNumber/attachments/:attachmentId/download` allows an owner, IT Staff, or Administrator to download only an active file. `DELETE /api/tickets/:ticketNumber/attachments/:attachmentId` is Requester-owner only and accepts `{ "removalReason": "No longer needed for troubleshooting." }`.

Attachment metadata is:

```json
{
  "id": 17,
  "originalName": "wifi-error.png",
  "mimeType": "image/png",
  "sizeBytes": 2048,
  "uploadedAt": "2026-09-13T10:01:00.000Z",
  "removedAt": null,
  "removalReason": null,
  "removedByUser": null
}
```

Removed files retain metadata but download returns safe `404 ATTACHMENT_NOT_FOUND`. Enforce the existing JPEG/PNG/WEBP/PDF extension/MIME/signature and 5 MiB rules, five-active-file limit, staging/compensation, and `409 ATTACHMENT_ALREADY_REMOVED`/`ATTACHMENT_LIMIT_REACHED` behavior.

## 5. Public Comments and Resolution Indication

### `GET /api/tickets/:ticketNumber/comments`

Requester owner, IT Staff, and Administrator may retrieve comments. Return `200`:

```json
{
  "comments": [
    {
      "id": 1,
      "content": "The issue still occurs after restarting.",
      "author": { "id": 1, "name": "Amina Rahman", "role": "REQUESTER" },
      "createdAt": "2026-09-13T10:02:00.000Z"
    }
  ]
}
```

### `POST /api/tickets/:ticketNumber/comments`

Requester owner, IT Staff, and Administrator may append `{ "content": "..." }`. Trim and enforce 1-2,000 characters. Return `201` with `{ "comment": <comment> }`; reject empty/oversized content with `400` and inaccessible Tickets with safe `404`.

### `POST /api/tickets/:ticketNumber/resolution-indication`

Requester owner only. No client timestamp or status is accepted. Return `200` with backend-generated `resolutionIndication` metadata. Repeated indication is idempotent. A Requester cannot set formal `RESOLVED` or `CLOSED`.

## 6. IT Staff Queue and Operations

### `GET /api/staff/tickets`

IT Staff and Administrators only. Query support:

- `search`: Ticket Number, Summary, Requester name, or Requester email, maximum 100 trimmed characters;
- filters `categoryId`, `relatedSystemId`, `requestedPriority`, `itPriority`, `status`, and `owner` (`me`, `unassigned`, or eligible User ID);
- `sort`: `updatedAt|createdAt|ticketNumber|summary|requestedPriority|itPriority|status|owner`;
- `order`: `asc|desc`;
- `page`: positive integer, default `1`; and
- `pageSize`: `10|25|50`, default `10`.

Return the same pagination shape as `GET /api/tickets`, with queue fields including requester display name, both priority badges, status, owner, created date, and updated date. Invalid parameters return `400`; inaccessible roles return `403`.

### `GET /api/staff/assignees`

IT Staff and Administrators only. Return active eligible assignment Users only:

```json
[{ "id": 8, "name": "Michael Brown", "email": "michael@example.test", "role": "IT_STAFF" }]
```

### `PATCH /api/staff/tickets/:ticketNumber/assignment`

IT Staff/Administrator. Body:

```json
{ "ownerUserId": 8, "confirm": true }
```

`ownerUserId: null` unassigns. Validate active staff/admin target and confirmation for reassign/unassign. Return `200` with updated owner or `404/409` as documented.

### `PATCH /api/staff/tickets/:ticketNumber/priority`

IT Staff/Administrator. Body `{ "itPriority": "URGENT" }`. Requested Priority remains unchanged. Return `200` with the updated Ticket or `400/404/409`.

### `PATCH /api/staff/tickets/:ticketNumber/status`

IT Staff/Administrator. Body `{ "status": "RESOLVED", "confirm": true }`. Enforce the transition matrix and confirmation rules transactionally; return `409 INVALID_STATUS_TRANSITION` for disallowed/stale changes.

## 7. Internal Notes

### `GET /api/tickets/:ticketNumber/internal-notes`

IT Staff/Administrator only. Return `{ "notes": [...] }` with `id`, plain-text `content`, author display data, and backend `createdAt`. Requesters receive `403` or the endpoint's safe role response without note content.

### `POST /api/tickets/:ticketNumber/internal-notes`

IT Staff/Administrator only. Body `{ "content": "..." }`, trim and enforce 1-2,000 characters, return `201 { "note": <note> }`, and never include it in Requester detail/comment responses.

## 8. Administrator User Management

### `GET /api/admin/users?search=&role=`

Administrator only. Search trimmed name/email up to 100 characters and optionally filter exactly one role. No mandatory pagination, multi-column sorting, or multiple filters. Return:

```json
{
  "users": [
    {
      "id": 8,
      "name": "Michael Brown",
      "email": "michael@example.test",
      "role": "IT_STAFF",
      "isActive": true,
      "mustChangePassword": false,
      "createdAt": "2026-09-13T10:00:00.000Z",
      "updatedAt": "2026-09-13T10:00:00.000Z"
    }
  ]
}
```

### `POST /api/admin/users`

Administrator only. Body:

```json
{
  "name": "Michael Brown",
  "email": "michael@example.test",
  "role": "IT_STAFF",
  "isActive": true,
  "initialPassword": "Initial-Lab3!Password"
}
```

Hash the initial password and set `mustChangePassword=true`; never return it. Return `201 { "user": <safe-user> }`; duplicate email is `409`.

### `PATCH /api/admin/users/:userId`

Administrator only. Accept only `name`, `email`, `role`, and `isActive`; reject unsupported fields. Enforce duplicate email, valid role, self-deactivation protection, last-active-Administrator protection, eligible assignment/session effects, and return `200` with the safe User.

### `POST /api/admin/users/:userId/initial-password`

Administrator only. Body `{ "initialPassword": "Reset-Lab3!Password" }`. Hash, set `mustChangePassword=true`, revoke target sessions, and return `200` with safe User data. Do not return the password.

## 9. Safe Error and Ownership Rules

All unexpected exceptions are logged server-side and mapped to safe `500`. A missing Ticket and a Ticket owned by another Requester use the same `404 TICKET_NOT_FOUND`; the same rule applies to Attachments, comments, notes, and downloads. UI controls improve feedback but never replace server checks. No endpoint accepts a client-created author, owner, role, status, timestamp, password hash, or storage path.
